Community Chat Guide

Lahat ng tungkol sa Community Chat ng ARKA: paano ito ginawa noong una, ano ang binago, saan ang frontend at backend, paano dumadaloy ang bawat mensahe, at ang ibig sabihin ng bawat salita at linya ng code.

Simula

Ano ang Community Chat?

Isang chat room para sa lahat ng tao sa iisang home office: Super Admin, Admins at Contractors. Parang group chat ng buong kumpanya.

Sino ang kasali?

Lahat ng naka-login at verified na user, kahit anong role. Kusa kang naidadagdag (join) sa unang beses na bubuksan o magpapadala ka.

Ilan ang room?

Isa bawat home office. Hindi nakikita ng ibang home office ang mga mensahe ninyo, kahit hulaan nila ang link.

Saan makikita?

Sa chat icon sa top bar, katabi ng notification bell, sa bawat page. Bubukas ang box sa kanang ibaba, parang Messenger.

Paano dumarating ang bagong mensahe?

Sa polling: nagtatanong ang browser sa server kada ilang segundo, "may bago ba?". Walang websocket server na kailangan.

Sino ang pwedeng mag-delete?

Ang nagpadala ng mensahe, o ang Super Admin (para sa moderation). Ang iba ay makakatanggap ng 403.

Ano ang limit?

Hanggang 2000 characters bawat mensahe, 30 mensahe kada minuto bawat user, at ang huling 100 na mensahe lang ang ipinapakita.

Isang linya para tandaan: Ang CommunityChat.jsx (frontend) ay nakikipag-usap sa CommunityChatController.php (backend) gamit ang JSON, at ang controller ay nag-iimbak sa 3 table: conversations, conversation_participants, messages.

Database

Ang 3 Table

Galing sa database/migrations/2026_10_20_100600_create_system_settings_and_chat_tables.php. Hindi ito nagbago mula Version 1.

conversations

idNumero ng room. PRIMARY KEY
typedirect, group o community. Sa ngayon, community lang ang gamit.
namePangalan ng room (pwedeng wala).
created_byUser na unang nagbukas. Dito nalalaman kung aling home office ang room. FK → users
timestampscreated_at, updated_at

conversation_participants

conversation_idAling room. FK → conversations
user_idSinong miyembro. FK → users
joined_atKailan sumali.
left_atKailan umalis (hindi pa ginagamit).
last_read_atKailan huling binasa. Batayan ng unread count.
PRIMARY KEY(conversation_id, user_id): isang beses lang pwedeng sumali ang isang user sa isang room.

messages

idNumero ng mensahe. PRIMARY KEY
conversation_idSaang room ipinadala.
user_idSino ang nagpadala.
bodyAng mismong mensahe (text).
timestampscreated_at = oras na ipinadala.
FK (composite)(conversation_id, user_id) → conversation_participants. Dapat miyembro muna bago makapag-send.

    Mga Error sa Chat

    Mga posibleng sirain sa chat, at kung ano ang lalabas. Tandaan: sa chat, maraming error ang hindi lumalabas sa screen dahil tahimik ang .catch(). Buksan lagi ang F12 → Network at tingnan ang request na feed o messages.

    Syntax

    Saan lalabas
    PHP: pulang page sa Network → Response ng request. JSX: Vite overlay / npm run build.

    Runtime

    Saan lalabas
    Network tab: status 500, 403, 404, 422. Console: TypeError. Log: storage/logs/laravel.log.

    Logic

    Saan lalabas
    Wala. Mali lang ang resulta: maling unread count, maling panig ng bubble, nakaka-delete ang hindi dapat.
