Ang Flow ng Isang Request

Sundan ang totoong code kapag nag-file ng leave ang contractor. Halos lahat ng ibang module (overtime, cash advance, devotional, attendance) ay ganito rin. Palitan lang ang pangalan ng file.

JSX form → route() → routes/*.php → middleware → Controller (validate) → Action (rules) → Model (DB) → back() / Inertia::render → JSX

    Ang 3 klase

    Anong Klase ng Error Ito?

    Unang tanong lagi: may error message ba? Doon mo malalaman kung anong klase.

    Syntax Error

    Ano ito
    Mali ang pagkakasulat (grammar ng code). Kulang ang ;, }, $…
    Kailan lumalabas
    Agad, bago pa tumakbo ang code.
    May message?
    Oo, may line number.
    Hirap

    Runtime Error

    Ano ito
    Tama ang sulat pero nag-crash habang tumatakbo. Hal. ginamit ang null.
    Kailan lumalabas
    Kapag naabot ang linyang may problema.
    May message?
    Oo, may line number at stack trace.
    Hirap

    Logic Error

    Ano ito
    Tumatakbo, walang error, pero mali ang resulta. Hal. && naging ||.
    Kailan lumalabas
    Kapag tiningnan mo ang data o output.
    May message?
    Wala. Ikaw ang huhuli.
    Hirap

    Checklist kapag pinag-debug ka

    1
    May salitang "syntax", "unexpected", "parse"? → Syntax. Pumunta sa line number, at tingnan din ang linya sa itaas nito.
    2
    May "undefined", "null", "not found", "SQLSTATE", "TypeError", o 403/404/500? → Runtime. Basahin ang unang file na nasa app/ o resources/js/ sa stack trace.
    3
    Walang error pero mali ang lumabas? → Logic. Ihambing ang dapat vs nangyari, hanapin ang if / kondisyon na nagpasya.
    4
    Ano ang binago? Patakbuhin ang git diff. Ipapakita nito ang eksaktong linyang binago o binura.
    Syntax

    Syntax Errors

    Mali ang pagkakasulat. Madalas ang tunay na mali ay isang linya bago ang sinabing line number.

    Backend Saan lalabas (PHP)

    • Pulang Laravel page: ParseError: syntax error, unexpected …
    • Check ng isang file: php -l app/Http/Controllers/Employee/LeaveRequestController.php

    Frontend Saan lalabas (JSX)

    • Terminal ng npm run dev o overlay sa browser: [plugin:vite:react-babel] Unexpected token (52:8)
    • Check ng lahat: npm run build
    SaanAno ang nawala / nabagoMali → TamaError na lalabas
    Runtime

    Runtime Errors

    Tama ang sulat pero nag-crash habang tumatakbo. Basahin ang unang linya ng message, tapos ang unang file na sa iyo (nasa app/ o resources/js/) sa stack trace.

    Logic

    Logic Errors

    Walang error message. Tanungin mo ang sarili: "Ano ang dapat mangyari, at ano ang nangyari?" Tapos hanapin ang linya na gumagawa ng desisyong iyon.

    Paano hanapin (5 hakbang)

    1
    Alamin ang inaasahan. Hal. "Dapat Pending approval."
    2
    Hanapin kung saan ito napagpapasyahan. I-search ang salita, hal. NeedsVerification.
    3
    Ilagay ang dd($needsVerification, $details, $proof); bago ang desisyon at subukan ulit.
    4
    Suriin ang mga operator: && / ||, !, === / !==, < / >=, ternary ? :.
    5
    Patakbuhin ang tests: php artisan test --filter=LeaveRequest. Ang babagsak na test ang magsasabi kung ano ang inaasahan.
